# CRM рекламаций на лифтовое оборудование

Одна база вместо Google-таблицы + ручного заполнения Трекера:
письмо клиента → карточка рекламации → автоответ с номером → назначение ответственного →
отработка по статусам (с письмами клиенту на нужных шагах) → закрытие → дашборд и отчёты.
Яндекс Трекер синхронизируется в обе стороны.

## Запуск (Windows)

1. Установите Python 3.11+ (галочка «Add to PATH»).
2. Двойной клик по `run.bat` — при первом запуске поставятся зависимости.
3. Откройте http://localhost:5000, вход `admin` / `admin` — **сразу смените пароль** (имя внизу слева → Профиль).
4. Загрузите текущий реестр: Настройки → Импорт реестра (или перетащите .xlsx на `import.bat`).
   Подтянутся все листы «Рекламации…», справочники компаний и узлов и список ответственных.
5. Настройки → Сотрудники: задайте пароли тем, кто будет работать, и e-mail для уведомлений.
6. Настройки → Почта и Трекер: подключите ящик рекламаций и Трекер (ниже).

Для работы в сети: на сервере/рабочем ПК запустите `run.bat`, остальные открывают `http://<имя-ПК>:5000`.
Linux: `./run.sh`. Данные — в папке `data/` (база `crm.sqlite3` + вложения писем). Бэкап = копия папки `data`.

## Как работает

**Регистрация**
* Из почты — автоматически каждые N минут (или кнопка «Проверить почту / Трекер»). Из письма распознаются
  заводские номера, адрес, телефон, узел; компания — по прошлым письмам с этого адреса/домена или по зав. номеру.
  Вложения сохраняются в карточке. Клиенту уходит подтверждение с номером `Р-26-00001`.
* Вручную — «+ Новая рекламация»: вставьте текст письма справа, поля заполнятся сами. По зав. номеру
  показываются прошлые рекламации этого лифта.

**Отработка** — в карточке:
* кнопки «Следующий шаг» — типовые переходы для текущего статуса; остальные — в «другой статус…»;
* ✉ у статуса — при переходе откроется готовое письмо клиенту по шаблону, его можно поправить перед отправкой;
* ответ клиента (по номеру в теме или цепочке) попадает в ту же карточку; если ждали уточнения — статус
  автоматически возвращается в «В процессе»;
* вся история (статусы, правки полей, письма, комментарии, Трекер) — в ленте справа;
* дата закрытия/отгрузки ставится автоматически, просрочка считается от контрольного срока.

Статусы = значения колонки «Отметка о выполнении» вашего реестра. Их группы, нормативы, письма и
соответствие статусам Трекера настраиваются в «Настройки → Статусы и сроки».

## Яндекс Трекер

1. Получите OAuth-токен (oauth.yandex.ru → создать приложение с правами `tracker:read`, `tracker:write`) и ID организации.
2. Включите интеграцию, нажмите «Проверить подключение» — появится список ключей статусов очереди.
3. В «Статусы и сроки» впишите для статусов CRM ключи статусов Трекера (по умолчанию стоят примерные:
   `open`, `inProgress`, `needInfo`, `secondLine`, `production`, `documentsReady`, `closed`, `rejected` —
   замените на реальные ключи вашей очереди MELBSSL).
4. У сотрудников заполните «Логин в Трекере».

Что синхронизируется: новая рекламация → задача в очереди; смена статуса → переход в Трекере
(если прямого перехода из текущего статуса нет, в ленте карточки будет предупреждение); ответственный → исполнитель;
комментарии → комментарии. Обратно: смена статуса и исполнителя в Трекере переносится в CRM.

**Переходный период.** Пока письма ещё падают в Трекер, можно включить «регистрировать в CRM задачи,
созданные в Трекере» и не включать приём почты в CRM. Когда будете готовы — переключите почту на CRM
и выключите автоматизацию создания задач из писем и автоответы в самом Трекере, чтобы не было дублей.

## Отчёты
* Дашборд: поступление по месяцам, открытые по статусам, нагрузка и просрочка по ответственным,
  возраст открытых, топ узлов/компаний/поставщиков, причины, гарантия/отказ, ПИК/сторонние, срок отработки.
* Отчёты: сводная по любому измерению (узел, компания, поставщик, причина, ответственный, месяц…) с выгрузкой в Excel.
* «Выгрузить в Excel» в реестре — файл в формате вашего реестра (те же колонки) с учётом фильтров.

Срок отработки и «в срок» считаются по дате закрытия — у импортированных записей её не было,
поэтому эти показатели наполнятся по мере работы в системе.

## Файлы
| файл | что внутри |
|---|---|
| app.py | веб-приложение, страницы, фоновая синхронизация |
| services.py | логика: регистрация, статусы, автоответы, распознавание писем, статистика |
| mailer.py | приём (IMAP) и отправка (SMTP) писем |
| tracker.py | API Яндекс Трекера |
| xlsx_io.py | импорт реестра и выгрузка в его формате |
| refs.py | статусы, поля карточки, шаблоны писем по умолчанию |
| db.py | схема базы |
